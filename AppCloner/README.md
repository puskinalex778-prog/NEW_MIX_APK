# App Cloner — клонер приложений для Android

Создаёт копию любого установленного приложения, которая ставится **рядом с оригиналом**: со своими данными, аккаунтами и своим названием. Например, два WhatsApp, два Telegram или отдельный аккаунт в игре.

Kotlin + Jetpack Compose (Material 3, Material You), Android 8.0+ (API 26–35).

## Возможности

- Список всех приложений: поиск, системные приложения, сортировка по имени, размеру и дате.
- Клон с **любым названием и именем пакета** (по умолчанию `оригинал.clone1`, `clone2`, …).
- Поддержка **split APK** (App Bundle из Google Play): все части переподписываются и ставятся одной сессией.
- **Приватность:** можно вырезать из клона разрешения (геолокацию, контакты, микрофон и т. д.).
- Опции `debuggable` и `allowBackup`.
- **Сохранение клона в файл** (`.apk` или `.apks` для SAI) вместо установки.
- Вкладка «Клоны»: запуск, настройки, удаление, повторное клонирование (обновление).
- Встроенный zipalign (16 КБ для `.so`) и подпись v1/v2/v3.

## Как это работает

1. Берётся `base.apk` (и split-части) установленного приложения.
2. В бинарном `AndroidManifest.xml` (через ARSCLib) меняется имя пакета, относительные имена классов становятся полными, переименовываются `authorities` провайдеров, собственные `permission`, `taskAffinity`, `process`; удаляются `sharedUserId`, `testOnly`, `instrumentation`.
3. Архив пересобирается без старой подписи, выравнивается и подписывается ключом Клонера (apksig).
4. Устанавливается через `PackageInstaller`.

Ключ для клонов создаётся при первой сборке и **хранится в памяти телефона с первого запуска** — поэтому клон можно пересоздать «поверх» (обновить) без удаления.

## Сборка через GitHub (без компьютера с Android Studio)

1. Создайте на GitHub новый репозиторий (можно приватный).
2. Загрузите в него **всё содержимое** этой папки. Важно: папку `.github` тоже. Она скрытая. Если загружаете через сайт, перетащите все файлы и папки разом.
   Или через git:
   ```bash
   git init && git add . && git commit -m "App Cloner"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГИН/AppCloner.git
   git push -u origin main
   ```
3. Откройте вкладку **Actions**. Сборка **Build APK** запустится сама (или нажмите *Run workflow*).
4. Через 3–6 минут откройте завершённый запуск → внизу раздел **Artifacts** → скачайте `AppCloner-apk` (внутри `AppCloner.apk`).
5. Если поставить тег `v1.0.0` (`git tag v1.0.0 && git push --tags`), APK появится ещё и в **Releases**.

### Чтобы обновлять Клонер без удаления (по желанию)

Без своего ключа каждая сборка подписывается новым debug-ключом, и новую версию придётся ставить после удаления старой. Если удалить Клонер, установленные клоны сохранятся, но обновить их «поверх» уже не получится.

Чтобы этого избежать, добавьте свой ключ в **Settings → Secrets and variables → Actions**:

| Секрет | Что это |
|---|---|
| `KEYSTORE_BASE64` | keystore в base64: `base64 -w0 my.jks` |
| `KEYSTORE_PASSWORD` | пароль keystore |
| `KEY_ALIAS` | alias ключа |
| `KEY_PASSWORD` | пароль ключа |
| `CLONER_KEY_BASE64` | *(необязательно)* свой PKCS12-ключ для подписи клонов, пароль и alias — `cloner` |

Создать keystore: `keytool -genkeypair -keystore my.jks -alias app -keyalg RSA -keysize 2048 -validity 10000`

## Первый запуск

1. Установите `AppCloner.apk` (разрешите установку из браузера/файлового менеджера).
2. Выберите приложение → задайте название → **Клонировать**.
3. При первой установке клона система попросит разрешить Клонеру устанавливать приложения: кнопка в диалоге откроет нужную настройку.
4. Если включена Play Защита, она может спросить про неизвестное приложение. Нажмите «Всё равно установить».

## Ограничения (честно)

Клон подписан другим ключом, поэтому:
- **Не будут работать** приложения с проверкой подписи или целостности: банки, многие игры с античитом, Play Integrity, защита вида `pairip`.
- **Вход через Google, Google Maps, push-уведомления Firebase** в клоне обычно не работают: они привязаны к оригинальной подписи и пакету.
- Если приложение жёстко прописало в коде имя своего FileProvider, функция «поделиться файлом» в клоне может падать.
- Системные приложения клонировать можно, но смысла обычно нет.

Хорошо клонируются обычные приложения без защиты: мессенджеры на открытых протоколах, клиенты соцсетей без входа через Google, утилиты, многие офлайн-игры.

Используйте только для приложений, которыми вы законно пользуетесь, и соблюдайте их условия использования.

## Структура

```
app/src/main/java/com/lopes/appcloner/
├── core/                 ← движок клонирования (чистая Java, тестируется на JVM)
│   ├── CloneEngine.java      пересборка, выравнивание, подпись
│   ├── ManifestPatcher.java  правка бинарного манифеста
│   └── CloneOptions.java
├── data/Apps.kt          ← список приложений, разрешения, иконки, хранилище клонов
├── install/Install.kt    ← ключ подписи, PackageInstaller, приём результата
├── ui/                   ← экраны Compose
├── MainViewModel.kt
└── MainActivity.kt
app/libs/                 ← ARSCLib и apksig (см. NOTICE.md)
```
